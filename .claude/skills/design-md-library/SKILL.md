# DESIGN.md library

84 DESIGN.md files, each describing how a real website looks: colours, typography, spacing, radii, components, imagery, motion and do's and don'ts. Source: https://github.com/VoltAgent/awesome-design-md (MIT, see `LICENSE`). Format: Google Stitch DESIGN.md.

## How to use it

1. Open `INDEX.md` — one line per site saying what its design is like. Pick 1–3 that match what the user asked for.
2. Read the chosen `library/<site>/DESIGN.md` in full.
3. Use it as a **reference for the system, not a costume**:
   - Take the *principles*: how much colour, type scale ratios, spacing rhythm, how photography is framed, how much motion, what the chrome does.
   - Do **not** copy the brand itself: no logos, product names, proprietary fonts (SF Pro, Circular, etc. → choose a close Google Font), trademark colours used as the client's identity, or copy text. The client's site must still look like the client.
   - If the project has its own `DESIGN.md` or palette, that wins; the library only informs decisions it leaves open.
4. When mixing two references, say which decision comes from which (e.g. "photo framing from Apple, type scale from Linear") in DECISIONES.md or your reply.
5. If the user names a site that is not in `INDEX.md`, say so and offer the closest ones from the index.
